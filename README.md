# Модуль бронирования учебных аудиторий

Курсовой проект по МДК.01.01 «Разработка программных модулей».
Тема 12: «Проектирование и разработка модуля бронирования учебных аудиторий».

## Состав решения

| Проект | Назначение |
|---|---|
| `src/RoomBooking.Core` | Предметная область: классы «Аудитория», «Бронирование», правила проверки данных (DomainException) |
| `src/RoomBooking.Web` | Веб-приложение ASP.NET Core Razor Pages, хранение данных в SQLite через EF Core, JSON API |

## Этап 3 (текущий)

- Бронирование аудитории на дату и время (`Reservations/New`), проверка заявки доменной службой `BookingPolicy`:
  аудитория в эксплуатации, вместимость, рабочее время 08:00–21:00, шаг 5 минут, продолжительность 30 минут — 6 часов,
  не в прошлом и не более чем на 60 дней вперёд, отсутствие пересечения с действующими бронированиями.
- Интервал времени — объект-значение `TimeSlot`; пересечение полуинтервалов: `a.Start < b.End && b.Start < a.End`.
- При пересечении выводится занятое время и список аудиторий, свободных на тот же интервал.
- Отмена бронирования с указанием причины (только до начала занятия); запись сохраняется в журнале.
- Состояние бронирования вычисляется по текущему времени: запланировано, идёт занятие, завершено, отменено.
- Расписание занятости всех аудиторий на день (шкала 08:00–21:00 и процент загрузки), недельное расписание аудитории.
- Поиск свободных аудиторий на интервал с учётом числа участников и проектора.
- JSON API: `GET /api/reservations`, `GET/POST /api/reservations`, `POST /api/reservations/{id}/cancel`,
  `GET /api/schedule/{дата}`, `GET /api/rooms/free`.

## Этап 2

- База данных SQLite `roombooking.db` создаётся автоматически по миграции `CreateRoomsAndReservations`.
- Сопоставление классов с таблицами задано через Fluent API (`Data/BookingContext.cs`), номер аудитории уникален.
- Каталог аудиторий с отбором; регистрация и изменение аудитории; вывод из эксплуатации и возврат.
